# crawl4ai, 8 Oct 2026

Looked at [crawl4ai](https://github.com/unclecode/crawl4ai) as a replacement for `ScraperService.scrape_price`. Do not add it.

## What buylog asks of a page

`buylog scrape` and `buylog scrape refresh` fetch one product URL and store a price, a currency, and a title on a quote. The current path is `requests` plus BeautifulSoup. It reads JSON-LD `Product` offers first, then `product:price:amount` and `og:price:amount` (and the matching currency meta tags), then a class / `itemprop` / `data-price` regex. A missing currency means the page did not say, and the caller falls back to the vendor's currency. `Quote.source_url` is what refresh uses later.

That works when the price is in the HTML. It does not run JavaScript, so a price painted by a script, or a page that refuses the request, comes back empty. It does not crawl a site, and it does not need the page rewritten as markdown.

## What crawl4ai is

The README describes it as an open-source crawler for LLMs and AI agents. The release on the default branch at the time of this note is v0.9.4 (23 Sep 2026). Apache-2.0, Python >= 3.10, which buylog's 3.13 requirement already satisfies.

Install is `pip install -U crawl4ai` and then `crawl4ai-setup`, which installs a browser. The library API is async: `AsyncWebCrawler().arun(url)` returns `result.markdown`. There is also a Docker/CLI mode and a hosted API at `api.crawl4ai.com` (`/scrape`, `/search`, `/answer`, `/extract`, MCP).

The library dependencies in its `pyproject.toml` include Playwright (>= 1.49), Patchright, playwright-stealth, a pinned `unclecode-litellm` (1.81.13), numpy, Pillow, lxml, BeautifulSoup, NLTK, and Pydantic, among others. Optional extras add PDF, torch, transformers, sentence-transformers (`cosine`), and Selenium (`sync`).

Structured extraction is separate from the markdown path. `JsonCssExtractionStrategy`, `JsonXPathExtractionStrategy`, and `RegexExtractionStrategy` do not call a model. `generate_schema` and `LLMExtractionStrategy` do. Markdown can be filtered with a pruning filter, BM25, or an LLM content filter.

## Why it does not fit

The common case is already covered. A retailer that publishes JSON-LD or an Open Graph price does not need a browser, a markdown conversion, or a model call. crawl4ai's non-LLM CSS and XPath extractors are the same idea as the selectors buylog already has, after a heavier fetch.

The gap that remains is JavaScript and bot walls. A headless browser would reach some of those pages. crawl4ai brings that browser, and also Playwright, Patchright, a LiteLLM pin, numpy, and NLTK, into a tool whose other jobs are SQLite and cron. `ScraperService` is synchronous. The library's main API is not. The torch and transformer extras are irrelevant to a price quote.

`LLMExtractionStrategy` is a poor default for `buylog scrape refresh`. A price that is already a meta tag should not wait on an API key, a model call, and a non-deterministic parse. The hosted API adds a key and a network service this local database does not have.

## If JavaScript pages matter later

A smaller step is an optional browser fetch in front of the existing extractors, used only when the plain request finds no price. The idea worth copying from crawl4ai, if that fetch exists, is a CSS or XPath schema with no model. The package itself stays out.
